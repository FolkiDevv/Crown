# Spec Delta

## Purpose

Определяет, какой трафик идёт через VPN в упрощённом интерфейсе: четыре режима, автоматическое распознавание белых списков в текущей сети, распознавание серверов для белых списков и политику автовыбора сервера для каждого режима.

## ADDED Requirements

### Requirement: Набор режимов трафика
Приложение MUST предлагать четыре режима: «Авто», «Умный», «Белые списки», «Только выбранные приложения». Режимом по умолчанию MUST быть «Авто». Выбранный режим MUST сохраняться между запусками и применяться к текущему подключению без ручного переподключения.

#### Scenario: Режим по умолчанию
- **WHEN** пользователь впервые открывает выбор режима
- **THEN** выбран «Авто»

#### Scenario: Смена режима при включённом VPN
- **WHEN** пользователь выбирает «Белые списки» при включённом VPN
- **THEN** через несколько секунд весь трафик идёт через VPN без ручного переподключения

### Requirement: Умный режим
В режиме «Умный» российские домены и IP-адреса MUST идти напрямую, а остальной трафик — через VPN. Правила MUST браться из записи «Bypass Russia» набора `Profile_Russia` снимка маршрутных профилей, MUST применяться в порядке этого профиля по принципу первого совпадения и MUST работать без сети при первом запуске за счёт копии, поставляемой с приложением.

#### Scenario: Российский сайт
- **WHEN** в режиме «Умный» открывается сайт в зоне .ru
- **THEN** соединение идёт напрямую, а не через VPN

#### Scenario: Зарубежный сайт
- **WHEN** в режиме «Умный» открывается зарубежный сайт, размещённый на зарубежном IP-адресе
- **THEN** соединение идёт через VPN

#### Scenario: Зарубежный домен на российском IP-адресе
- **GIVEN** зарубежный домен не совпадает ни с одним доменным правилом профиля «Bypass Russia», стоящим раньше правила российских IP-адресов
- **WHEN** в режиме «Умный» открывается этот домен, и он разрешается в российский IP-адрес
- **THEN** первым совпадает правило российских IP-адресов, и соединение идёт напрямую; приложение не добавляет собственных правил поверх порядка профиля

### Requirement: Режим белых списков
В режиме «Белые списки» весь трафик, включая российские ресурсы, MUST идти через VPN; напрямую MUST идти только трафик локальной и частной сети и трафик приложений из списка «Приложения без VPN». DNS-запросы приложений из списка «Приложения без VPN» MUST идти напрямую, DNS-запросы всех остальных приложений MUST идти через туннель, а адреса серверов VPN до подключения MUST разрешаться через DNS-сервер из белого списка, заданный в конфигурации проверок.

#### Scenario: Российский сайт при белых списках
- **WHEN** в режиме «Белые списки» открывается сайт в зоне .ru
- **THEN** соединение идёт через VPN

#### Scenario: Смена сервера при белых списках
- **WHEN** в режиме «Белые списки» пользователь выбирает другой сервер или «Авто» пересобирает набор серверов
- **THEN** ни одно соединение не уходит в сеть мимо VPN, пока новое ядро запускается: оно получает тот же VPN-интерфейс (требование `proxy-connection` «In-place restart keeps traffic inside the tunnel»; смена набора приложений, маршрутов или флага metered меняет интерфейс или сеть VPN, и там защищает только «Постоянный VPN» с блокировкой)

#### Scenario: Разрешение адреса сервера
- **GIVEN** публичные зарубежные DNS-серверы в сети недоступны
- **WHEN** приложение подключается к серверу, заданному доменным именем
- **THEN** имя сервера разрешается через DNS-сервер из белого списка, и подключение устанавливается

### Requirement: Обновление подписок при белых списках
Когда активен режим белых списков и VPN подключён, обновление подписок MUST выполняться через туннель.

#### Scenario: Автообновление подписки
- **GIVEN** активен режим белых списков, VPN подключён, адрес подписки не входит в белый список
- **WHEN** наступает время автообновления подписки
- **THEN** подписка успешно обновляется через туннель

### Requirement: Режим «Только выбранные приложения»
В режиме «Только выбранные приложения» через VPN MUST идти трафик только выбранных пользователем приложений; трафик остальных приложений MUST идти напрямую.

#### Scenario: Приложение не выбрано
- **WHEN** в этом режиме приложение, которого нет в списке, открывает сайт
- **THEN** соединение идёт напрямую

### Requirement: Область приложений зависит от режима
Список приложений режима «Только выбранные приложения» MUST действовать только в этом режиме. В остальных режимах трафик всех приложений, кроме списка «Приложения без VPN», MUST обрабатываться правилами маршрутизации выбранного режима, а трафик приложений из этого списка MUST идти напрямую. Оба списка MUST сохраняться при смене режима, и при возврате в «Только выбранные приложения» MUST снова действовать прежний выбор. Смена области приложений MUST NOT менять выбранный сервер.

#### Scenario: Переход из режима приложений в «Белые списки»
- **GIVEN** в режиме «Только выбранные приложения» выбран только браузер
- **WHEN** пользователь переключается на «Белые списки»
- **THEN** трафик всех приложений, кроме списка «Приложения без VPN», идёт через VPN по правилам режима белых списков

#### Scenario: Правила режима для всех приложений в «Умном»
- **GIVEN** выбран режим «Умный», браузер не входит в «Приложения без VPN»
- **WHEN** браузер открывает сайт в зоне .ru
- **THEN** соединение идёт напрямую по правилам умного режима, а не принудительно через VPN

#### Scenario: Возврат в режим приложений
- **WHEN** пользователь снова выбирает «Только выбранные приложения»
- **THEN** через VPN снова идёт только браузер, выбор не потерян

### Requirement: Пустой список выбранных приложений
Режим «Только выбранные приложения» MUST NOT применяться с пустым списком приложений: пока список пуст, режим MUST NOT выбираться, а если список опустел при активном режиме, приложение MUST переключиться на «Авто» и сообщить об этом в настройках. Пустой список MUST NOT приводить к тому, что через VPN идёт трафик всех приложений.

#### Scenario: Выбор режима с пустым списком
- **GIVEN** ни одно приложение не выбрано
- **WHEN** пользователь выбирает «Только выбранные приложения»
- **THEN** сначала открывается выбор приложений, и режим включается только после выбора хотя бы одного

#### Scenario: Список опустел при активном режиме
- **GIVEN** активен режим «Только выбранные приложения»
- **WHEN** пользователь снимает выбор со всех приложений
- **THEN** режим переключается на «Авто», в настройках показано сообщение об этом, и ни в какой момент через VPN не идёт трафик всех приложений по пустому списку

### Requirement: Определение белых списков в сети
Приложение MUST определять состояние текущей сети проверкой в обход туннеля по двум наборам адресов из конфигурации: разрешённым и неразрешённым. Если доступен хотя бы один разрешённый адрес и недоступен ни один неразрешённый, сеть MUST считаться сетью с белыми списками. Если не доступен ни один адрес, сеть MUST считаться сетью без интернета, а не сетью с белыми списками.

#### Scenario: Белые списки
- **WHEN** разрешённые адреса отвечают, а все неразрешённые недоступны
- **THEN** сеть отмечается как сеть с белыми списками

#### Scenario: Обычная сеть
- **WHEN** доступен хотя бы один неразрешённый адрес
- **THEN** сеть отмечается как обычная

#### Scenario: Нет интернета
- **WHEN** не отвечает ни один адрес из обоих наборов
- **THEN** сеть отмечается как сеть без интернета, и режим трафика не меняется

### Requirement: Проверка в обход туннеля
Проверки белых списков MUST выполняться через физическую сеть устройства в обход туннеля VPN, чтобы результат не зависел от того, включён ли VPN.

#### Scenario: Проверка при включённом VPN
- **GIVEN** VPN включён и работает
- **WHEN** выполняется проверка белых списков
- **THEN** запросы проверки идут через физическую сеть, и при белых списках неразрешённые адреса оказываются недоступны

### Requirement: Моменты проверки белых списков
Пока VPN включён, проверка MUST выполняться при подключении VPN, при каждой смене сети, при выборе режима «Авто» пользователем и каждые 15 минут в мобильной сети. Независимо от состояния VPN проверка MUST выполняться при запуске «Починки». При выключенном VPN никакие другие проверки MUST NOT выполняться. «Авто» MUST NOT применять результат, полученный в другой физической сети: до результата для текущей сети действуют правила умного режима.

#### Scenario: Выбор «Авто» при выключенном VPN
- **GIVEN** VPN выключен
- **WHEN** пользователь выбирает режим «Авто», а позже подключает VPN
- **THEN** при выборе «Авто» проверка не выполняется, а при подключении VPN выполняется проверка текущей сети

#### Scenario: Повторный выбор «Авто» после ручной смены
- **GIVEN** VPN включён, пользователь вручную выбрал «Белые списки», и это отбросило незавершённую проверку
- **WHEN** пользователь снова выбирает «Авто»
- **THEN** запускается новая проверка текущей сети, до её результата действуют правила умного режима, а результат, сохранённый для прежней сети, не применяется

#### Scenario: Смена сети
- **GIVEN** VPN включён в режиме «Авто»
- **WHEN** устройство переходит с Wi-Fi на мобильную сеть
- **THEN** выполняется проверка, и её результат применяется к режиму

#### Scenario: VPN выключен
- **WHEN** VPN выключен и устройство меняет сеть
- **THEN** проверка не выполняется

### Requirement: Результат проверки относится только к своей сети
Проверки MUST выполняться по одной: новая проверка отменяет незавершённую. Результат MUST применяться, только если это результат последней запущенной проверки, физическая сеть проверки всё ещё текущая (сеть VPN не учитывается), а режим, в котором проверка началась, не менялся вручную с момента её старта. Остальные результаты MUST отбрасываться. Маршрутизацию меняет только результат в режиме «Авто»; в других режимах результат лишь сохраняется для подсказки вне зоны белых списков.

#### Scenario: Смена сети во время проверки
- **GIVEN** проверка в сети Wi-Fi ещё не завершилась
- **WHEN** устройство переходит в мобильную сеть с белыми списками, проверка мобильной сети обнаруживает белые списки, а затем завершается проверка Wi-Fi с результатом «обычная сеть»
- **THEN** результат проверки Wi-Fi отброшен, и действует режим белых списков

#### Scenario: Две проверки в одной сети
- **GIVEN** в мобильной сети идёт проверка по таймеру
- **WHEN** во время неё начинается проверка при запуске «Починки», которая обнаруживает белые списки
- **THEN** проверка по таймеру отменена, её результат не применяется, и действует режим белых списков

#### Scenario: Ручная смена режима во время проверки
- **GIVEN** выбран режим «Авто», и проверка сети ещё не завершилась
- **WHEN** пользователь вручную выбирает «Белые списки», а затем проверка завершается с результатом «обычная сеть»
- **THEN** результат проверки отбрасывается, и действует выбранный пользователем режим «Белые списки»

#### Scenario: Проверка при включённом VPN
- **GIVEN** VPN включён, и сетью по умолчанию для приложения является VPN
- **WHEN** проверка в физической мобильной сети завершается
- **THEN** её результат применяется, потому что физическая сеть не менялась

### Requirement: Применение результата в режиме «Авто»
В режиме «Авто» приложение MUST использовать правила умного режима в обычной сети и правила режима белых списков в сети с белыми списками. Смена эффективного режима MUST применяться автоматически, без уведомлений; о ней MUST сообщать только карточка режима на главной.

#### Scenario: Обнаружены белые списки
- **GIVEN** режим «Авто», VPN подключён
- **WHEN** проверка обнаруживает белые списки
- **THEN** маршрутизация и выбор сервера переключаются на режим белых списков, уведомление не показывается, а карточка режима на главной показывает «Авто · белые списки»

### Requirement: Проверка сети при настройках для белых списков
Настройками для белых списков MUST считаться режим «Белые списки» и сервер для белых списков, выбранный вручную (в любом режиме); управляемые селекторы «Авто» MUST NOT считаться такими настройками. Пока они действуют, проверки из «Моментов проверки белых списков» MUST выполняться в любом режиме, а выбор таких настроек пользователем при включённом VPN MUST запускать проверку. Вне «Авто» результат MUST только сохраняться и MUST NOT менять маршрутизацию.

#### Scenario: Выбор режима «Белые списки» при включённом VPN
- **GIVEN** VPN подключён в режиме «Умный»
- **WHEN** пользователь выбирает «Белые списки»
- **THEN** выполняется проверка текущей сети, её результат сохраняется, а маршрутизация остаётся маршрутизацией «Белых списков»

### Requirement: Подсказка вне зоны белых списков
Пока VPN подключён, действуют настройки для белых списков, а последняя проверка текущей физической сети показала обычную сеть, приложение MUST показывать на главной карточку-предупреждение и MUST публиковать уведомление со звуком в отдельном канале уведомлений. Сеть без интернета и сеть, ещё не проверенная, MUST NOT вызывать предупреждение.

#### Scenario: Вернулся домой в режиме «Белые списки»
- **GIVEN** VPN подключён в режиме «Белые списки»
- **WHEN** устройство переходит в Wi-Fi, и проверка находит обычную сеть
- **THEN** на главной появляется карточка «Вы вне зоны белых списков», и приходит уведомление со звуком с кнопками «Включить «Авто»» и «Включить «Умный»»

#### Scenario: Сервер для белых списков в обычном режиме
- **GIVEN** VPN подключён в режиме «Умный», выбран вручную сервер «RU LTE обход БС»
- **WHEN** проверка находит обычную сеть
- **THEN** показывается предупреждение о сервере для белых списков, а маршрутизация режима «Умный» не меняется

### Requirement: Повтор и снятие подсказки вне зоны белых списков
Уведомление MUST повторяться со звуком каждые 15 минут, пока условие подсказки сохраняется. Карточка и уведомление MUST исчезать, когда пользователь сменил настройки, сеть сменилась, проверка нашла белые списки или VPN выключен.

#### Scenario: Повтор уведомления
- **GIVEN** предупреждение показано, и пользователь ничего не менял
- **WHEN** проходит 15 минут
- **THEN** уведомление приходит снова со звуком; если за это время пользователь сменил режим или сервер, уведомление снимается и больше не повторяется

### Requirement: Действия подсказки вне зоны белых списков
Карточка и уведомление MUST предлагать ровно два действия: «Включить «Авто»» (рекомендуемое, выделено в карточке и стоит первым в уведомлении) и «Включить «Умный»». Действие MUST делать выбранный режим режимом трафика, а выбранный вручную сервер для белых списков MUST заменять селектором «Авто». Варианта оставить настройки для белых списков без напоминаний MUST NOT быть.

#### Scenario: Включить «Авто»
- **WHEN** пользователь нажимает «Включить «Авто»» в карточке или уведомлении
- **THEN** режим становится «Авто», сервер для белых списков, выбранный вручную, заменяется селектором «Авто», карточка и уведомление исчезают

#### Scenario: Включить «Умный»
- **GIVEN** VPN подключён в режиме «Белые списки» в обычной сети
- **WHEN** пользователь нажимает «Включить «Умный»»
- **THEN** режим становится «Умный», карточка и уведомление исчезают

#### Scenario: Кнопка уведомления, когда приложение выгружено
- **GIVEN** VPN подключён с настройками для белых списков в сети без белых списков, Android выгрузил процесс интерфейса, служба VPN работает
- **WHEN** пользователь нажимает «Включить «Умный»» или «Включить «Авто»» в уведомлении
- **THEN** приложение узнаёт у службы её состояние и, раз она подключена, перезапускает работающий VPN на месте с выбранным режимом за несколько секунд; если служба в этот момент ещё подключается, перезапуск откладывается до «Подключено» и не отправляется в незавершённый старт

### Requirement: Распознавание серверов для белых списков
Сервер MUST считаться сервером для белых списков, если его название содержит одно из ключевых слов из конфигурации (без учёта регистра). Иных способов отнесения сервера к этой категории MUST NOT быть, и пользователь MUST NOT иметь возможности изменить это решение.

#### Scenario: Ключевое слово в названии
- **WHEN** сервер называется «RU LTE обход БС»
- **THEN** он распознаётся как сервер для белых списков

#### Scenario: Ключевого слова нет
- **WHEN** название сервера не содержит ни одного ключевого слова
- **THEN** он не распознаётся как сервер для белых списков, и в интерфейсе нет способа отнести его к этой категории вручную

### Requirement: Автовыбор сервера по режиму
При выборе сервера «Авто» в обычной сети приложение MUST выбирать лучший рабочий сервер из всех, кроме серверов для белых списков, а если таких рабочих нет — лучший рабочий сервер для белых списков. В сети с белыми списками приложение MUST сначала выбирать лучший рабочий сервер для белых списков, а при отсутствии рабочих — лучший рабочий из остальных.

#### Scenario: Обычная сеть
- **WHEN** «Авто» выбирает сервер в обычной сети и хотя бы один обычный сервер отвечает
- **THEN** выбирается лучший из отвечающих обычных серверов, серверы для белых списков не выбираются

#### Scenario: Обычная сеть, работает только сервер для белых списков
- **WHEN** «Авто» выбирает сервер в обычной сети, ни один обычный сервер не отвечает, а сервер для белых списков отвечает
- **THEN** выбирается отвечающий сервер для белых списков

#### Scenario: Белые списки, есть рабочий сервер для белых списков
- **WHEN** «Авто» выбирает сервер в сети с белыми списками и хотя бы один сервер для белых списков отвечает
- **THEN** выбирается лучший из отвечающих серверов для белых списков

#### Scenario: Белые списки, серверы для белых списков не отвечают
- **WHEN** ни один сервер для белых списков не отвечает, но отвечает обычный сервер
- **THEN** выбирается лучший отвечающий обычный сервер

### Requirement: Ручной выбор сервера сохраняется
Если пользователь выбрал конкретную страну или сервер, а не «Авто», режим «Авто» MUST менять только маршрутизацию и MUST NOT менять выбранный сервер.

#### Scenario: Выбран конкретный сервер
- **GIVEN** пользователь выбрал сервер «Германия 2»
- **WHEN** обнаруживаются белые списки
- **THEN** маршрутизация переключается на режим белых списков, а сервер остаётся «Германия 2»

### Requirement: Конфигурация проверок и ключевых слов
Наборы адресов для проверки, DNS-серверы из белого списка и ключевые слова MUST поставляться с приложением и MUST обновляться вместе с маршрутными профилями через то же зеркало. Повреждённая или неполная загруженная конфигурация MUST отклоняться с сохранением предыдущей рабочей.

#### Scenario: Обновление конфигурации
- **WHEN** выполняется обновление маршрутных профилей и в источнике есть более новая конфигурация проверок
- **THEN** приложение начинает использовать новую конфигурацию

#### Scenario: Повреждённая конфигурация
- **WHEN** загруженная конфигурация не проходит проверку формата
- **THEN** она отклоняется, а продолжает действовать предыдущая

### Requirement: Приватность проверок
Запросы проверки MUST обращаться только к адресам из конфигурации и MUST NOT содержать идентификаторов пользователя, устройства или его серверов. Результаты проверок MUST оставаться на устройстве.

#### Scenario: Содержимое запроса проверки
- **WHEN** выполняется запрос проверки
- **THEN** он содержит только фиксированный адрес из конфигурации и стандартные заголовки, без идентификаторов пользователя и его серверов
