# Spec Delta

## Purpose

Функция «Починка»: последовательно проверяет всё, от чего зависит работа VPN, сама исправляет безопасные неисправности и даёт пользователю понятный вердикт либо отчёт для специалиста.

## ADDED Requirements

### Requirement: Запуск «Починки»
«Починку» MUST можно запустить из верхней кнопки раздела «Настройки» и из баннера проблемы на главной. Она MUST работать как при включённом, так и при выключенном VPN, и MUST позволять остановить проверку в любой момент.

#### Scenario: Запуск при выключенном VPN
- **WHEN** пользователь запускает «Починку» при выключенном VPN
- **THEN** проверка начинается и показывает ход выполнения

#### Scenario: Остановка
- **WHEN** пользователь нажимает «Остановить» во время проверки
- **THEN** проверка прекращается, а уже сделанные автоматические исправления откатываются (кроме обновления подписки и маршрутных профилей, содержимое которых остаётся)

### Requirement: Набор и порядок проверок
«Починка» MUST выполнять по порядку проверки: интернет без VPN; белые списки в сети; время на устройстве; частный DNS Android и другие VPN; DNS напрямую; подписка; доступность серверов; DNS через VPN; сайты через VPN; российские сайты напрямую; работа в фоне. Каждая проверка MUST показывать результат и короткое пояснение.

#### Scenario: Ход проверки
- **WHEN** «Починка» выполняется
- **THEN** проверки выполняются в указанном порядке, у текущей виден индикатор, а у завершённых — результат и пояснение

### Requirement: Зависимые проверки
Если проверка не может быть выполнена из-за неудачи предыдущей, она MUST отмечаться как «не проверено» с причиной и MUST NOT отмечаться как ошибка.

#### Scenario: Нет рабочего сервера
- **GIVEN** ни один сервер не отвечает
- **WHEN** доходит очередь до проверки «Сайты через VPN»
- **THEN** она отмечена «не проверено: нет рабочего сервера», а не ошибкой

### Requirement: Сервер для проверок через VPN
Сервер для проверок «DNS через VPN» и «Сайты через VPN» MUST выбирать проверка «доступность серверов»: текущий сервер, если он отвечает, иначе лучший отвечающий по правилам автовыбора текущего режима. Если отвечающего сервера нет, обе проверки MUST отмечаться «не проверено».

#### Scenario: Текущий сервер не отвечает
- **GIVEN** текущий сервер не отвечает, а другой сервер подписки отвечает
- **WHEN** выполняется проверка «доступность серверов»
- **THEN** для проверок через VPN выбирается отвечающий сервер, и именно он используется в «DNS через VPN» и «Сайты через VPN»

### Requirement: Подключение для проверок через VPN
Если VPN выключен, VPN другого приложения не активно и проверка «доступность серверов» выбрала сервер, «Починка» MUST включить VPN на этом сервере для проверок «DNS через VPN» и «Сайты через VPN» и MUST оставить его включённым, если после проверки всё работает.

#### Scenario: Проверка сайтов при выключенном VPN
- **GIVEN** VPN этого приложения выключен, VPN другого приложения не активно, согласие на VPN дано, серверы отвечают
- **WHEN** «Починка» доходит до проверки «Сайты через VPN»
- **THEN** VPN включается, сайты проверяются через него, и при успехе VPN остаётся включённым

### Requirement: Согласие на VPN и чужое VPN при проверках через VPN
Если активно VPN другого приложения, «Починка» MUST NOT включать свой VPN, и проверки «DNS через VPN» и «Сайты через VPN» MUST отмечаться «не проверено» до устранения конфликта пользователем. Если согласия на VPN нет и VPN другого приложения не активно, «Починка» MUST показать стандартный системный запрос согласия; при отказе обе проверки MUST отмечаться «не проверено: нет разрешения на VPN».

#### Scenario: Нет согласия на VPN, пользователь отказал
- **GIVEN** согласие на VPN не дано, VPN другого приложения не активно, серверы отвечают
- **WHEN** «Починка» доходит до проверок через VPN, показывает системный запрос согласия, и пользователь отказывается
- **THEN** VPN не включается, а «DNS через VPN» и «Сайты через VPN» отмечены «не проверено: нет разрешения на VPN»

#### Scenario: Активно VPN другого приложения
- **GIVEN** VPN этого приложения выключен, а VPN другого приложения активно
- **WHEN** «Починка» доходит до проверок «DNS через VPN» и «Сайты через VPN»
- **THEN** свой VPN не включается, разрешение другого приложения не отзывается, а обе проверки отмечены «не проверено: активно VPN другого приложения»

### Requirement: Проверка времени на устройстве
«Починка» MUST сравнивать время устройства со временем, полученным из ответа доверенного сервера, и при расхождении более 60 секунд MUST сообщать о проблеме и предлагать открыть системные настройки даты и времени.

#### Scenario: Часы отстают
- **WHEN** время устройства отличается от эталонного на 7 минут
- **THEN** проверка времени отмечена как проблема, и есть кнопка перехода к настройкам даты и времени

### Requirement: Проверка частного DNS и других VPN
«Починка» MUST обнаруживать включённый вручную частный DNS Android и активное VPN другого приложения и MUST предлагать перейти в соответствующие системные настройки. Отсутствие согласия пользователя на VPN для этого приложения MUST NOT считаться признаком VPN другого приложения.

#### Scenario: VPN другого приложения в системе
- **WHEN** в системе активно VPN другого приложения
- **THEN** проверка отмечена как проблема с пояснением и кнопкой перехода в системные настройки VPN

#### Scenario: Нет согласия на VPN после новой установки
- **GIVEN** приложение только что установлено, согласие на VPN ещё не дано, других VPN нет
- **WHEN** выполняется проверка частного DNS и других VPN
- **THEN** проблема «активно VPN другого приложения» не сообщается

### Requirement: Безопасные автоматические исправления
«Починка» MUST автоматически выполнять только обратимые исправления в пределах приложения: переключение на рабочий сервер, смену DNS напрямую на DNS из белого списка, смену DNS через VPN на альтернативный, обновление подписки, обновление маршрутных профилей, снижение MTU до 1280. Каждое выполненное исправление MUST быть отмечено «исправлено» у соответствующей проверки.

#### Scenario: DNS провайдера не отвечает
- **WHEN** проверка «DNS напрямую» не получает ответа от текущего DNS-сервера
- **THEN** приложение переключается на DNS из белого списка, повторяет проверку и при успехе отмечает её «исправлено»

### Requirement: Откат неудачного исправления
Если автоматическое исправление не устранило проблему, «Починка» MUST вернуть изменённую настройку к прежнему значению. Откатываются только настройки, записанные самой «Починкой», и только пока в них остаётся записанное ею значение. Обновление подписки и маршрутных профилей MUST NOT откатываться: полученное от провайдера содержимое и выбор сервера, сделанный самим обновлением, остаются.

#### Scenario: Снижение MTU не помогло
- **GIVEN** сайты через VPN не открываются при отвечающем сервере
- **WHEN** приложение снижает MTU до 1280, а сайты по-прежнему не открываются
- **THEN** MTU возвращается к прежнему значению

### Requirement: Системные настройки только по действию пользователя
«Починка» MUST NOT менять настройки Android самостоятельно; для них MUST показываться кнопка перехода в нужный раздел системных настроек.

#### Scenario: Оптимизация батареи
- **WHEN** проверка «Работа в фоне» обнаруживает, что Android может остановить VPN
- **THEN** показывается кнопка «Разрешить работу в фоне», и настройка меняется только после действия пользователя

### Requirement: Итоговый вердикт
По завершении «Починка» MUST показать один из трёх итогов: «Исправили сами» с описанием исправления; «Причина найдена» с понятным описанием и шагами для пользователя; «Причину определить не удалось» с основной кнопкой экспорта отчёта.

#### Scenario: Белые списки, в подписке нет серверов для них
- **WHEN** обнаружены белые списки, ни один сервер не отвечает, и среди серверов пользователя нет ни одного, распознанного как сервер для белых списков
- **THEN** итог «Причина найдена»: в сети белые списки, а в подписке нет серверов для них; предлагается попросить такой сервер у VPN-сервиса или подключиться к Wi-Fi

#### Scenario: Белые списки, серверы для них не отвечают
- **WHEN** обнаружены белые списки, среди серверов есть распознанные как серверы для белых списков, но ни один сервер не отвечает
- **THEN** итог «Причина найдена»: серверы для белых списков сейчас не отвечают, вероятно, проблема на стороне VPN-сервиса; утверждение об отсутствии таких серверов в подписке не показывается

#### Scenario: Подписка закончилась
- **WHEN** срок подписки истёк или трафик исчерпан
- **THEN** итог «Причина найдена» с предложением продлить подписку у VPN-сервиса

#### Scenario: Нет интернета
- **WHEN** проверка «Интернет без VPN» неудачна
- **THEN** итог «Причина найдена»: проблема не в VPN, на устройстве нет интернета

#### Scenario: Причина неизвестна
- **WHEN** серверы отвечают, но сайты через VPN не открываются, и исправления не помогли
- **THEN** итог «Причину определить не удалось», основная кнопка — «Экспортировать отчёт»

### Requirement: Совет о «Постоянном VPN»
Под итогом «Починки» MUST показываться совет включить для Crown «Постоянный VPN» и «Блокировать соединения без VPN» с кнопкой перехода в системные настройки VPN, если блокировка соединений без VPN не включена (Android 10 и выше, где состояние можно прочитать). Совет MUST предупреждать, что приложения без VPN тогда останутся без интернета.

#### Scenario: Блокировка выключена
- **WHEN** «Починка» завершилась, а у Crown не включено «Блокировать соединения без VPN»
- **THEN** под итогом показан совет с кнопкой «Настройки VPN»; настройка меняется только действием пользователя

#### Scenario: Блокировка включена
- **WHEN** «Починка» завершилась, а у Crown включены «Постоянный VPN» и «Блокировать соединения без VPN»
- **THEN** совет не показывается

### Requirement: Экспорт отчёта
При любом итоге пользователь MUST иметь возможность экспортировать отчёт одним архивом через системное меню «Поделиться». Отчёт MUST содержать результаты всех проверок с пояснениями и временем, выполненные исправления, журнал ядра за последние минуты, итоговую конфигурацию, версии Android, приложения и ядра, а также тип сети.

#### Scenario: Экспорт после неизвестной причины
- **WHEN** пользователь нажимает «Экспортировать отчёт»
- **THEN** открывается системное меню «Поделиться» с одним архивом отчёта

### Requirement: Отчёт без секретов
Перед упаковкой отчёт MUST быть очищен как минимум по правилам экспорта журнала и дополнительно MUST NOT содержать адресов и доменов серверов пользователя (в том числе хостов внутри URL) и ссылок подписок; они заменяются обезличенными метками. Правила экспорта журнала этим требованием не меняются.

#### Scenario: Проверка содержимого отчёта
- **WHEN** специалист открывает экспортированный отчёт
- **THEN** в нём нет паролей, ключей, UUID, адресов серверов и ссылок подписок пользователя

#### Scenario: Адрес сервера внутри URL в журнале
- **GIVEN** строка журнала ядра содержит URL, хост которого — домен сервера пользователя
- **WHEN** отчёт упаковывается
- **THEN** домен в этом URL заменён обезличенной меткой

### Requirement: Без автоматической отправки
«Починка» MUST NOT отправлять отчёт или результаты проверок за пределы устройства без явного действия пользователя. Сетевые запросы, которые сами являются проверками (DNS-запросы, запросы к адресам из конфигурации проверок, проверки серверов и сайтов), MAY выходить за пределы устройства и MUST NOT содержать результатов проверок или сведений из отчёта.

#### Scenario: Завершение без экспорта
- **WHEN** пользователь закрывает экран «Починки», не нажимая экспорт
- **THEN** отчёт и результаты проверок не покидают устройство; за его пределы ушли только сами проверочные запросы, без результатов проверок
