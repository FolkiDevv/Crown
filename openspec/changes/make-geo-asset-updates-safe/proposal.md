# Proposal

> **Категория:** надёжность · **Приоритет:** низкий · **Проверка:** подтверждено по коду · **Код:** upstream · **Объём:** S

## Why

### Находка
Файлы `geoip.dat`/`geosite.dat` для Xray-профилей с правилами `geoip:`/`geosite:` заменяются небезопасно в двух местах.

1. **Смена источника сразу удаляет рабочий файл.** Экран «Ядро → Геоданные Xray» при выборе другого провайдера или правке URL:
   ```kotlin
   // app/src/main/java/io/nekohasekai/sagernet/ui/settings/XrayGeoSettingsScreen.kt:93-99
   private fun setUrl(file: String, url: String): Boolean {
       val preference = pref<EditTextPreference>(urlKey(file))
       if (preference.text == url) return false
       preference.text = url
       XrayGeoAssets.delete(file)
       return true
   }
   ```
   Новый файл качается только при следующем старте профиля (`bg/proto/BoxInstance.kt:94-110`, `ensureXrayAssets`). В этот
   момент VPN не подключён, и запрос идёт напрямую: через прокси — только при `serviceConnected()`
   (`bg/XrayGeoAssets.kt:224`). Если новый источник напрямую недоступен (блокировка хостинга, опечатка в своём URL,
   captive-портал), старт падает, а рабочая копия уже удалена. Сама загрузка атомарна (временный файл и `renameTo`,
   `XrayGeoAssets.kt:217-271`), но предварительное удаление эту защиту обходит.
2. **Принимается любой непустой ответ 200.** `fetch` проверяет только код ответа, отсутствие перехода с https на http и
   ненулевой размер (`XrayGeoAssets.kt:238-242`, `:262`), затем переименовывает файл в рабочий (`:264`). Тип содержимого,
   формат (geoip/geosite — списки protobuf) и разумный минимальный размер не проверяются. Реальный путь к HTML с кодом 200 —
   ссылка на страницу файла GitHub (`…/blob/<ветка>/geosite.dat`) вместо raw-ссылки или ссылки на релиз; так же ведут себя
   зеркала, отдающие заглушку с 200. После этого файл «установлен» навсегда: `installed()` = файл есть и не пуст (`:112`),
   а старт качает только отсутствующие (`BoxInstance.kt:97`).

Диагностика при этом вводит в заблуждение: `describeFailure` (`XrayGeoAssets.kt:302-317`) для установленного файла без
«failed to open» в ошибке сообщает «в geosite.dat нет категории X» — пользователь ищет не ту категорию вместо того, чтобы
перекачать файл. Какой текст ошибки даёт Xray на HTML вместо protobuf — из Kotlin не видно (предположение).

### Влияние
Затрагивает только Xray-профили и полные Xray-конфиги с geo-правилами. Смена источника при недоступном новом адресе или
неверная ссылка — и такие профили, а также их пробы в тестах, перестают запускаться при каждом старте; автоматического
восстановления нет, вернуть рабочее состояние можно только сетью до нового источника или ручной перекачкой. Сценарий требует
действия пользователя в настройках, поэтому приоритет низкий; для пользователей с блокировками он неприятен тем, что
ломает уже работавший VPN.

### Как воспроизвести
Шаги выведены из кода и не прогонялись.
1. Xray-профиль (например, VLESS через Xray) с маршрутом или полным конфигом, где есть `geosite:` правило; геофайлы
   скачаны, VPN работает.
2. Сценарий удаления: Настройки → Ядро → Геоданные Xray → «Свой» источник, URL geosite — на несуществующий хост. Сразу
   проверить `adb shell run-as dev.folki.crown.debug ls files` — `geosite.dat` исчез. «Применить» → старт падает с ошибкой
   загрузки geosite.dat.
3. Сценарий HTML: URL geosite — страница файла на GitHub (`https://github.com/<репозиторий>/blob/<ветка>/geosite.dat`).
   Запустить профиль: файл скачан (`adb shell run-as dev.folki.crown.debug head -c 64 files/geosite.dat` начинается с
   `<!DOCTYPE html>`), старт падает с сообщением про отсутствующую категорию; повторный старт падает так же без загрузки.

## What Changes
- Рекомендуется: не удалять файл при смене источника. Запоминать источник, из которого файл скачан (рядом с файлом или в
  настройке); при несовпадении с текущим перекачивать на старте или по «Скачать сейчас» атомарно поверх старого, а при ошибке
  оставлять старый с предупреждением «используются данные прежнего источника».
- Проверять скачанное до переименования: начало файла — запись protobuf (первый байт `0x0A`), не `<`; отклонять
  `Content-Type: text/html`; минимальный размер — единицы КБ. Неверный ответ — понятная ошибка «по ссылке не файл данных,
  проверьте адрес», рабочий файл не трогается.
- В `describeFailure` различать «нет категории» и «файл не читается»; во втором случае предлагать перекачать.
- Подсказка в настройках: ссылку вида `github.com/…/blob/…` предлагать заменить на raw-адрес.
- Проверка: шаги 2–3 — рабочий файл на месте, профиль стартует со старыми данными, загрузка HTML отклонена с понятной ошибкой.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `routing-rules`: в «Rule set references» добавляется — смена источника данных geo не удаляет рабочую копию до успешной
  загрузки и проверки новой; ответ, не являющийся файлом данных, отвергается.

## Impact
- **Код:** `bg/XrayGeoAssets.kt`, `ui/settings/XrayGeoSettingsScreen.kt`; `bg/proto/BoxInstance.kt` — проверка «источник файла
  совпадает с текущим».
- **Upstream:** все файлы — код upstream вне точек правки; нужна новая точка правки или патч в upstream (там то же поведение).
- **Ядро throne, сборка, инструменты:** ядро не меняется; разбор текста ошибок Xray в `describeFailure` — на стороне приложения.
- **Риски:** старый файл от другого провайдера может не содержать категорий нового правила — это покрывает сообщение «нет
  категории»; работающий старый файл лучше отказа старта. Проверка первого байта не гарантирует целостность; полная проверка —
  разбор ядром, если оно даёт такую функцию.
- **Проверка исправления:** шаги «Как воспроизвести»; юнит-тест на проверку формата (HTML отклонён, валидный protobuf принят).
- **Внешние источники:** нет.
