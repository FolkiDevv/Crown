# Proposal

> **Категория:** надёжность · **Приоритет:** средний · **Проверка:** подтверждено по коду ·
> **Код:** Crown (вызов стоит в точке правки 7 upstream-файла) · **Объём:** S

## Why

### Находка
Файл `simple/config.json` содержит пробы для распознавания белых списков, DNS белых списков, ключевые слова серверов
для белых списков (`wlKeywords`) и хосты проверки времени. Design D7 обещает, что он обновляется по сети «рядом с
обновлением маршрутных профилей (точка 7) и с тем же интервалом», «чтобы владелец форка мог обновлять списки без
выпуска приложения» (`openspec/changes/simple-ui-redesign/design.md`, D7).

В коде единственный вызов — внутри обновления удалённого маршрутного профиля:

```kotlin
// app/src/main/java/io/nekohasekai/sagernet/group/RemoteRouteUpdater.kt:71-78
private fun refreshRuleSetList() {
    synchronized(ruleSetListLock) {
        ...
        RouteRepo.refresh()?.let { Logs.w("routeprofiles refresh before a remote route update: $it") }
        io.nekohasekai.sagernet.simple.config.SimpleConfigRepo.refresh()?.let { Logs.w(it) }
    }
}
```

`refreshRuleSetList()` вызывается только из `fetchInto()` (`RemoteRouteUpdater.kt:59`). Периодически `fetchInto` запускает
`RemoteRouteUpdater.UpdateTask`, но `schedule()` отменяет работу, пока `route_auto_update < 30`
(`RemoteRouteUpdater.kt:197-199`), а по умолчанию настройка выключена:

```kotlin
// app/src/main/java/io/nekohasekai/sagernet/database/SettingsRegistry.kt:195
@JvmField val ROUTE_AUTO_UPDATE = int("route_auto_update", -1440)
```

simple эту настройку не включает: её пишет только экран классических настроек
(`ui/settings/NetworkSettingsScreens.kt:265`, `:272`). Для подписок simple сам включает автообновление, для маршрутов —
нет. В итоге `SimpleConfigRepo.refresh()` выполняется только:
- один раз, когда создаётся профиль «Умный» (`simple/modes/TrafficModes.kt:172` → `RemoteRouteUpdater.addRemote`);
- в шаге «Починки», который обновляет маршруты (`simple/repair/DeviceRepairFixes.kt:287`);
- при ручном обновлении маршрута в классическом интерфейсе.

Буква требования спецификации («обновляться вместе с маршрутными профилями») соблюдена, но маршрутные профили при
настройках по умолчанию сами не обновляются, поэтому обещанное D7 обновление без выпуска не происходит.

Сам профиль «Умный» по той же причине тоже не обновляется, хотя создан с `auto_update = true`
(`TrafficModes.kt:162-165` обещает «kept up to date by RemoteRouteUpdater»). Последствия здесь скромнее: доменные
списки в нём — удалённые rule-set'ы, которые ядро перекачивает раз в 24 часа, пока VPN работает
(`outbound/config/ConfigGenerator.kt:1462-1464`). Устаревает только состав правил профиля.

### Влияние
На обычной установке simple (классические настройки не трогали) пробы, DNS белых списков и `wlKeywords` остаются такими,
какими были в выпуске приложения. Когда владелец меняет `config.json` в репозитории — например, чтобы исправить ложное
распознавание белых списков, заменить недоступный DNS или добавить ключевое слово серверов провайдера, — исправление
доходит только до тех, кто запустил «Починку» или установил новую версию. Пользователь этого не замечает, а ошибки
распознавания режима сети остаются у всех пользователей simple с настройками по умолчанию. Сейчас вшитая и удалённая
копии совпадают, поэтому вреда пока нет; механизм срабатывает впервые при первой правке файла без выпуска.

### Как воспроизвести
Шаги выведены из кода, не прогонялись.
1. Чистая установка debug-сборки, simple-интерфейс, добавить подписку, выбрать режим «Умный».
2. `adb shell run-as dev.folki.crown.debug ls -l files/simple/` — запомнить время изменения `config.json` (или его
   отсутствие, если первая загрузка не удалась).
3. `adb shell dumpsys jobscheduler | grep -A3 dev.folki.crown.debug` — есть задачи подписок и проверки обновлений,
   периодической задачи `RemoteRouteUpdater` нет.
4. Перевести дату вперёд на 2 дня (или подождать сутки), открыть приложение, включить и выключить VPN: время изменения
   `files/simple/config.json` и `remote_last_update` профиля «Умный» не меняются; в logcat нет строк `simple config` и
   `Updating remote routing profile`.
5. Тест: юнит-тест на планировщик с `route_auto_update` по умолчанию — работа отменяется; после исправления тест должен
   проверять, что обновление конфигурации simple запланировано.

## What Changes
- Рекомендуется: в коде Crown (`app/src/simple/`) завести собственную периодическую работу WorkManager по образцу
  планировщика подписок: воркер в процессе `:bg`, ограничение «есть сеть», раз в сутки. Она вызывает
  `SimpleConfigRepo.refresh()` и `RemoteRouteUpdater.update()` для управляемого профиля «Умный». Ставить её при старте
  приложения из хуков simple. Глобальная настройка классики и другие удалённые маршруты пользователя не затрагиваются.
- Если «Умный» обновился при работающем VPN, применять изменение так же, как классика (`SubscriptionQueue.reloadNeeded`,
  `RemoteRouteUpdater.kt:111`), или по правилам simple для смены режима.
- Альтернатива дешевле: при первом запуске simple, пока ключа `route_auto_update` нет, включить его (1440 минут) и вызвать
  `RemoteRouteUpdater.schedule()`. Минус — начнут обновляться все удалённые маршруты пользователя, а явный выбор
  «выключено» в классике придётся отличать от значения по умолчанию.
- Частичная мера: вызывать `SimpleConfigRepo.refresh()` после успешного обновления подписки (хук
  `onSubscriptionRefreshed`) не чаще раза в сутки.
- Проверка: после исправления в шаге 3 видна периодическая задача; после принудительного запуска
  (`adb shell cmd jobscheduler run -f dev.folki.crown.debug <job-id>`) время изменения `files/simple/config.json` меняется.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `traffic-modes` (в `openspec/changes/simple-ui-redesign/specs/`): требование «Конфигурация проверок и ключевых слов»
  уточняется — конфигурация обновляется периодически при настройках по умолчанию, независимо от переключателя
  автообновления маршрутов классического интерфейса; профиль «Умный» обновляется вместе с ней.

## Impact
- **Код:** новый планировщик в `app/src/simple/` (например, рядом с `SimpleConfigRepo`), хуки simple при старте;
  `RemoteRouteUpdater.kt` — без изменений (вызывается существующий `update`).
- **Upstream:** код Crown; правка upstream не нужна. Существующая точка 7 (`RemoteRouteUpdater.kt`) остаётся как есть.
  Воркер для `:bg` использует уже объявленный `RemoteWorkerService`.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** 2–3 запроса в сутки к GitHub или jsDelivr на устройство. Одновременное обновление из двух процессов уже
  защищено файловой блокировкой в `SimpleConfigRepo.refresh()`. Обновлённый «Умный» при работающем VPN требует
  перезагрузки — без неё изменения применятся при следующем подключении.
- **Проверка исправления:** шаги 3–4 до и после; юнит-тест планировщика.
- **Внешние источники:**
  - WorkManager, периодическая работа и ограничения: https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work
