# Proposal

> **Категория:** надёжность · **Приоритет:** низкий · **Проверка:** подтверждено по коду · **Код:** upstream · **Объём:** S

## Why

### Находка
Приёмник загрузки объявлен выключенным
(`app/src/main/AndroidManifest.xml:451-460`, `android:enabled="false"`) и включается только вызовом
`PackageManager.setComponentEnabledSetting` (`app/src/main/java/io/nekohasekai/sagernet/BootReceiver.kt:13-21`). Таких вызовов три:
- при каждом старте сервиса: `bg/BaseService.kt:627`, `BootReceiver.enabled = DataStore.rememberEnable`;
- переключатель «Автоподключение» в классическом интерфейсе: `ui/settings/GeneralSettingsScreens.kt:55`;
- переключатель в simple: `app/src/simple/.../simple/settings/SettingsViewModel.kt:159`.

Сама настройка `remember_enable` хранится в таблице `settings` (`database/SettingsRegistry.kt:149`), не входит в
`DEVICE_LOCAL_KEYS` (`:399-405`) и поэтому переносится резервной копией приложения; файл БД входит и в системный Auto Backup
(`res/xml/backup_descriptor.xml`, `res/xml/backup_rules.xml`). Состояние компонента ни в одну копию не входит, а
восстановление (`ui/BackupFragment.kt:428-474` → `triggerFullRestart`) его не трогает.

Проверка в `BootReceiver.onReceive` (`if (!DataStore.rememberEnable) { enabled = false; return }`) работает только в одну
сторону: выключенный компонент сигнал загрузки не получает вовсе. `PackageReplacedReceiver` всегда включён, но срабатывает
только на обновление приложения, не на загрузку.

### Влияние
- Перенос на новое устройство или переустановка с восстановлением из облака: настройка «включено», компонент выключен.
- Восстановление файла копии поверх установки, где автоподключение было выключено: то же.
Пока пользователь хоть раз не запустит VPN вручную, после перезагрузки VPN не поднимается, хотя экран настроек показывает
«Автоподключение» включённым. Чаще всего это касается ТВ-приставок и устройств «настроил и забыл», куда настройки переносят
копией. Последствие — работа без VPN до ручного запуска. Сценарий редкий, исправление дешёвое.

### Как воспроизвести
Шаги выведены из кода и не прогонялись.
1. Установка A: включить «Автоподключение», выбрать сервер, сделать резервную копию.
2. Установка B: `adb shell pm clear dev.folki.crown.debug`, восстановить копию из шага 1. VPN вручную не запускать.
3. `adb shell dumpsys package dev.folki.crown.debug | grep -A3 disabledComponents` — `io.nekohasekai.sagernet.BootReceiver`
   выключен, хотя «Автоподключение» в настройках включено.
4. `adb reboot` — после загрузки VPN не поднят (ожидается: поднят).

## What Changes
- Рекомендуется: синхронизировать состояние компонента с настройкой при старте процесса приложения, в фоновом потоке и
  только при расхождении: `BootReceiver.enabled = DataStore.rememberEnable`.
- Дополнительно — сразу после успешного восстановления копии, до перезапуска приложения.
- Системный Auto Backup — отдельный путь: при нём `SagerNet.onCreate` не выполняется, и синхронизация при старте
  процесса не сработает, пока приложение не запустят. Вариант — `BackupAgent.onRestoreFinished`, включающий компонент
  по восстановленной настройке. `DataStore` и `BootReceiver.enabled` там недоступны (они опираются на
  `SagerNet.application`): настройку нужно прочитать из восстановленной БД напрямую, а компонент переключить через
  контекст агента. Нужно проверить, получает ли только что восстановленное и ни разу не открытое
  приложение `BOOT_COMPLETED`: по документации Android приложение в состоянии «остановлено» его не получает, и тогда
  до первого открытия автозапуск невозможен при любом исправлении.
- Проверка: шаги 3–4 после восстановления показывают включённый компонент, VPN поднимается после перезагрузки.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `proxy-connection`: в «External control actions» уточняется — автоподключение при загрузке следует сохранённой настройке,
  в том числе после восстановления копии и переноса на другое устройство.

## Impact
- **Код:** место синхронизации при старте процесса (`SagerNet.kt` или код Crown, выполняемый при старте); после
  восстановления — `database/backup/BackupRestore.kt` или `ui/BackupFragment.kt`.
- **Upstream:** `SagerNet.kt` — существующая точка идентичности форка (`FORK_IDENTITY_POINTS`), но с новым назначением —
  описание нужно расширить; `BackupRestore.kt`/`BackupFragment.kt` — новая точка правки. Можно и патчем в upstream: там то же
  поведение.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** `setComponentEnabledSetting` с `DONT_KILL_APP` дёшев, но рассылает `PACKAGE_CHANGED` — вызывать только при
  расхождении. Альтернатива «компонент всегда включён, решение в `onReceive`» поднимала бы процесс `:bg` при каждой загрузке и
  у тех, у кого автоподключение выключено, — upstream именно этого избегает.
- **Проверка исправления:** шаги «Как воспроизвести»; юнит-тест не нужен.
- **Внешние источники:**
  - `PackageManager.setComponentEnabledSetting`: https://developer.android.com/reference/android/content/pm/PackageManager#setComponentEnabledSetting(android.content.ComponentName,%20int,%20int)
