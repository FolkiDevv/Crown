# Proposal

> **Категория:** скорость, надёжность · **Приоритет:** высокий · **Проверка:** воспроизведено на эмуляторе (открытие раздела);
> подтверждено по коду (запуск после обновления подписки) · **Код:** Crown (+ upstream для записи результатов) · **Объём:** M

## Why

### Находка
Раздел «Серверы» simple UI при каждом показе запускает фоновую проверку задержек — URL-тест **всех** серверов всех подписок:

```kotlin
// app/src/simple/java/io/nekohasekai/sagernet/simple/SimpleActivity.kt:1141-1142
// Opening the section reads the list again and starts the background delay check (simple-ui 5.3).
LaunchedEffect(servers) { servers.opened() }
```

`ServersViewModel.opened()` → `reload(thenTest = true)` (`simple/servers/ServersViewModel.kt:213-241`) → `startUrlTest()`
(`ServersViewModel.kt:540-547`):

```kotlin
val all = mutableState.value.sections?.allServers?.map { it.id }.orEmpty()
val throttled = lastUrlTest > 0L && now - lastUrlTest < TEST_INTERVAL_MS      // 2 мин, :747
val ids = if (throttled) all.filter { it !in testedIds } else all
…
if (!TestSessionClient.startProfiles(TestSpec.KIND_URL, ids)) return
```

Потолка нет; после раунда — до 30 проверок IP выхода через внешний сервис (`startIpTest`, `:586-608`, `IP_TEST_LIMIT = 30`).
Сессия идёт в `:bg` с foreground-уведомлением и не привязана к видимости раздела: уход на главную или закрытие приложения её не
останавливает. `lastUrlTest` живёт только в памяти ViewModel, поэтому после пересоздания activity или процесса интервал в 2 минуты
начинается заново.

Второй вход в тот же путь — **завершение любого обновления подписки**, в том числе планового в фоне. `ServersViewModel` создаётся
вместе с `SimpleActivity` (`SimpleActivity.kt:168`, `by viewModels()`), даже если раздел ни разу не открывали, и в `init` слушает
очередь подписок без учёта жизненного цикла (`ServersViewModel.kt:187-189`). По окончании обновления:

```kotlin
// ServersViewModel.kt:510-521
if (finished.isEmpty()) return
mutableEvents.tryEmit(ServersEvent.Updated)
lastUrlTest = 0L            // снимает ограничение «не чаще раза в 2 мин»
reload(thenTest = true)
```

— полный раунд тестов и IP-проверок, хотя пользователь на главной или приложение в фоне. Задача 5.3 (`tasks.md`) задумывала проверку
«при открытии раздела».

Каждый результат в `:bg` сохраняется отдельно: `ProfileManager.saveUrlTestResult` (`database/ProfileManager.kt:495-500`) =
`getProfile(id)` с разбором outbound + `UPDATE` в своей транзакции; каждая будит Room InvalidationTracker обоих процессов.

### Влияние
Замер (эмулятор Android 17, release-сборка, подписка 3000 серверов на один локальный сервер, VPN выключен): одно нажатие на вкладку
«Серверы» и сразу назад на главную.
- Сессия шла **4 мин 12 с** с уведомлением «URL test · 3000 selected profiles» (на 3,5-й минуте «2247 / 3000 · 2005 OK · 242 failed»).
- ЦП `:bg` по `/proc/<pid>/stat`: utime +800, stime +20 144 тиков → ≈209 с ЦП за 252 с (≈83 % ядра), большая часть — в ядре ОС
  (тысячи соединений; на эмуляторе сетевой стек дороже, на телефоне доля будет меньше). UI-процесс — ≈20 с ЦП.
- atrace за 10 с раунда: 99 `UPDATE profiles SET latency…`, 299 `SELECT * FROM profiles WHERE id = ?`, 64 транзакции.
- Пока идёт раунд, тестовая сессия занята: «Починка» отметила «Доступность серверов» и «DNS через VPN» как «Не проверено: идёт
  другой тест»; ручная проверка сервера отвечает «занято».
- На реальной сети это 3000 соединений с серверами провайдера и HTTP-запросы к тестовому URL при каждом заходе в раздел чаще раза в
  2 минуты и после каждого обновления подписки (при интервале провайдера 1–6 ч — несколько раундов в сутки), плюс до 30 запросов к
  сервису определения IP. Расход батареи и трафика, фоновая служба, которой пользователь не просил, всплеск соединений у провайдера.

Спецификация `simple-ui-redesign/specs/simple-ui` проверки всех серверов не требует: «Определение страны сервера» нуждается в IP-проверке
только серверов без страны в названии, «Структура списка серверов» и карточки — в задержке страны.

### Как воспроизвести
1. Release-сборка, подписка на ~3000 серверов (тестовый макет: N строк `ss://…#XX Server N`).
2. Подождать > 2 мин после последнего открытия «Серверов» (или перезапустить приложение).
3. Открыть «Серверы», через 2 с вернуться на главную.
4. `adb shell dumpsys notification --noredact | grep -A30 pkg=dev.folki.crown` — уведомление «URL test · 3000 selected profiles» с
   растущим счётчиком; каждые 10 с `cat /proc/$(pidof dev.folki.crown:bg)/stat` — utime/stime растут ≈4 мин.
5. Путь после обновления (по коду, не запускался): подписка ≥ 50 серверов, остаться на главной, обновить подписку кнопкой на
   карточке или дождаться планового обновления — после его окончания в logcat `:bg` стартует сессия `KIND_URL` по всем серверам,
   затем `KIND_IP`, хотя «Серверы» не открыты.

## What Changes
1. **(Рекомендуется) Тест только по открытию раздела.** Завершение обновления подписки лишь помечает список устаревшим; перечитка и
   тест — при следующем показе раздела, а если раздел сейчас видим (activity STARTED и выбрана вкладка) — сразу. Нужен признак
   видимости (`opened()`/`closed()` из `ServersSection` через `DisposableEffect` + жизненный цикл activity). Путь после
   добавления подписки (`AddEvent.Added` → `reload(thenTest = true)`, `SimpleActivity.kt:270`) — пользовательский, остаётся.
2. **Потолок раунда.** Тестировать то, что нужно для показа: по несколько серверов на страну (лучшие по прошлым результатам и
   непроверенные), серверы без страны в названии — для IP-проверки (с потолком, как `IP_TEST_LIMIT`), серверы раскрытой страны — при
   раскрытии; общий потолок на раунд (например, 100–200). Остальное — по мере раскрытия и прокрутки.
3. **Интервал вне памяти:** время последнего раунда хранить в `SharedPreferences("simple_ui")` (только UI-процесс), чтобы
   пересоздание activity не снимало ограничение. Одного времени мало: набор уже проверенных серверов (`testedIds`,
   `ServersViewModel.kt:147`) тоже живёт в памяти, и после пересоздания ветка «в пределах интервала» (`:544-545`) сочтёт
   непроверенными все серверы. Поэтому «покрыт раундом» определяется без памяти процесса: сервер, у которого в БД есть
   результат теста не старше сохранённого времени раунда, считается проверенным (либо набор id хранится вместе со
   временем и очищается с началом нового раунда). В пределах интервала тестируются только серверы, добавленные после раунда,
   и серверы прерванного раунда, до которых он не дошёл (п. 4), — в пределах того же потолка раунда.
4. **Своя сессия останавливается**, если раздел скрыт дольше нескольких секунд (`TestSessionClient.stop()` при `ownTest != NONE`);
   незаконченные серверы доделываются при следующем открытии.
5. **Запись результатов пачками** (дополнительно, upstream): одна транзакция на 50–100 результатов, `UPDATE` без предварительного
   `getProfile` — меньше пробуждений InvalidationTracker обоих процессов.

Проверка: тот же сценарий — сессия не больше потолка, ЦП `:bg` после захода в раздел < 10 с, уведомления дольше нескольких секунд нет;
после обновления подписки на главной — ни одной тестовой сессии (счётчик `startTest` в logcat `:bg` за сутки с автообновлением
до/после); «Починка» во время открытого раздела не получает «идёт другой тест» дольше раунда.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `simple-ui-redesign/specs/simple-ui`: «Структура списка серверов»/«Определение страны сервера» — фоновая проверка задержек и IP
  выполняется при показе раздела, ограничена объёмом, нужным для показа стран и серверов без страны в названии, и не запускается,
  пока раздел скрыт.
- `connectivity-testing`: «Batch testing» — автоматические (не запрошенные пользователем) раунды ограничены по числу профилей.

## Impact
- **Код:** `simple/servers/ServersViewModel.kt`, `simple/SimpleActivity.kt` (признак видимости раздела); при п.5 —
  `database/ProfileManager.kt`, `bg/test/TestSession.kt`.
- **Upstream:** п.1–4 — код Crown; п.5 — upstream-файлы вне списков (новая точка правки или патч в upstream).
- **Ядро throne, сборка:** не затрагиваются.
- **Риски:** у редко раскрываемых стран и серверов задержка дольше остаётся «неизвестной» — закрывается ленивыми тестами при
  раскрытии; страны серверов без страны в названии определяются только при открытии раздела — это и есть задуманное поведение.
  Автовыбор ведёт свои проверки (`AutoSelectorProfiles`) и от этого раунда не зависит — проверить.
- **Проверка исправления:** замер выше; unit-тест выбора id раунда (страны, серверы без страны, потолок).
- **Внешние источники:** не требуются.
