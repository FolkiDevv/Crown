# Proposal

> **Категория:** надёжность · **Приоритет:** низкий · **Проверка:** воспроизведено на эмуляторе · **Код:** Crown · **Объём:** S

## Why

### Находка
Перед открытием классического экрана выбора приложений (`AppManagerActivity`) простой интерфейс подменяет **живые** ключи
per-app, по которым `:bg` строит TUN, а прежние значения сохраняет только в `SavedStateHandle`:

```kotlin
// app/src/simple/java/io/nekohasekai/sagernet/simple/modes/ModesViewModel.kt:148-161
fun edit(list: AppList, openAppList: (AppList) -> Unit) {
    ...
    saved[KEY_PRE_PROXY_APPS] = DataStore.proxyApps
    saved[KEY_PRE_BYPASS] = DataStore.bypass
    saved[KEY_PRE_INDIVIDUAL] = DataStore.individual
    ...
    DataStore.proxyApps = true
    DataStore.bypass = list == AppList.BYPASS
    DataStore.individual = apps.joinToString("\n")
```

Прежние значения возвращаются (`restorePreEditScope`, `:206-214`) только из `appListClosed` (`:166`), то есть когда
`AppManagerActivity` вернула результат. Смерть процесса при живой задаче учтена: `SavedStateHandle` восстанавливается, и
`init` продолжает правку (`:84-101`, `resuming`). Но если задачу смахнули из «Недавних» (или activity уничтожена иначе без
возврата результата), `SavedStateHandle` теряется: новый `ModesViewModel` видит `editing == null` и применяет режим заново,
только если режим не сохранён или include-список пуст (`TrafficModeApplier.hasEmptyIncludeList`, `TrafficModeApplier.kt:406-407`,
— проверяет только `proxyApps && !bypass && пусто`). Иначе вызывается лишь `ensure()`, и «временные» ключи остаются
действующими.

### Влияние
Режим «Только выбранные приложения», пользователь открыл «Приложения без VPN» и смахнул задачу: в настройках остаётся
`proxyApps=true, bypass=true, individual=<список без VPN>` — при следующем подключении (или перезагрузке от наблюдателя сети)
**все** приложения, кроме этого списка, идут через VPN, хотя выбран режим «только выбранные». Карточка режима на главной
показывает «Умный» вместо «Только выбранные» — интерфейс противоречит выбранному режиму. Состояние не проходит само: до
следующей смены режима или списка. Обратный случай (утечка мимо VPN при правке списка выбранных в «Авто») через интерфейс
недостижим: пункт «Выбранные приложения» показывается только в этом режиме (`SettingsScreen.kt:228`). Частота низкая.

### Как воспроизвести
Эмулятор Android 17, debug-сборка `0a0fcc4e`, простой интерфейс.
1. «Настройки» → «Selected apps only» → в открывшемся списке отметить одно приложение → «Назад». Ключи (чтение БД через
   `run-as`): `simple_mode=apps`, `proxyApps=true`, `bypassMode=false`, `individual=<приложение>,<свой пакет>`.
2. «Настройки» → «Apps without VPN» (открывается классический список). Ключи сразу становятся `bypassMode=true`,
   `individual=""`.
3. Открыть «Недавние» и смахнуть карточку Crown.
4. Открыть приложение. Фактически: `simple_mode=apps`, но `proxyApps=true`, `bypassMode=true`, `individual=""` — область
   «все приложения через VPN»; главная показывает «Traffic mode, Smart». Ожидаемо: прежние ключи режима «только выбранные».

## What Changes
1. (рекомендуется) Хранить «ключи до правки» не в `SavedStateHandle`, а в собственном ключе настроек (например,
   `simple_apps_edit_pending`) рядом с правкой. При старте `ModesViewModel`, если отметка есть, а правка не продолжается
   (`editing == null`), вернуть ключи и применить режим (`TrafficModeApplier.apply`). Так уже устроен `PendingImports`
   (сеанс процесса и восстановление при старте).
2. Альтернатива: не трогать живые ключи вовсе — передавать списку отдельный «черновой» набор (потребует правки
   `AppManagerActivity`, то есть upstream; поэтому вариант 1 предпочтительнее).
3. Дешёвая страховка: при старте `ModesViewModel` без продолжающейся правки сравнивать текущую область per-app с
   `TrafficModePlan.scope(mode, …)` и при расхождении применять режим. Минус — перезапишет осознанную правку из классического
   интерфейса, которую простой интерфейс по замыслу оставляет до смены режима.

Проверка: сценарий выше — после повторного открытия ключи режима «только выбранные», карточка «Только выбранные приложения».

## Impact
- **Код:** `simple/modes/ModesViewModel.kt` (`edit`, `init`, `appListClosed`), хранение отметки — рядом с `TrafficModes`.
- **Upstream:** код Crown (вариант 1 и 3); вариант 2 потребовал бы патча `AppManagerActivity`.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** восстановление при старте не должно срабатывать, пока правка действительно продолжается (процесс пересоздан при
  живой задаче) — признак `editing` из `SavedStateHandle` остаётся главным, отметка на диске — запасной.
  Возвращённые ключи доходят до работающего VPN только перезагрузкой (`make-service-state-reliable-across-processes`).
- **Проверка исправления:** сценарий выше; JVM-тест: отметка на диске без `editing` → ключи возвращаются.
