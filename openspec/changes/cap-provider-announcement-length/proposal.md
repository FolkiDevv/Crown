# Proposal

> **Категория:** скорость, стабильность · **Приоритет:** низкий · **Проверка:** гипотеза (факты кода подтверждены,
> задержка не измерена) · **Код:** оба (разбор — upstream, показ — Crown) · **Объём:** S

## Why

### Находка
Текст объявления провайдера приходит из ответа подписки — это недоверенные данные. Длина нигде не ограничивается:

```kotlin
// app/src/main/java/io/nekohasekai/sagernet/group/SubscriptionMetadata.kt:45-48
decodeHeaderValue(header("Announce")).takeIf { it.isNotEmpty() }?.let {
    info.announce = it
    info.valid = true
}
```

`decodeHeaderValue` раскрывает значение `base64:…` без предела (`SubscriptionMetadata.kt:111-120`). Ограничение задаёт
только транспорт: блок заголовков HTTP/1 в OkHttp — до 256 КиБ, то есть после base64 до ~190 тысяч символов. Из тела
ответа объявление берётся только из первых 16 384 символов (`HEAD_CHARS`, `:14`). simple тоже не обрезает:
`announce.trim()` (`app/src/simple/java/io/nekohasekai/sagernet/simple/subs/SubscriptionState.kt:74`).

Лист «Объявление» в simple показывает текст целиком:

```kotlin
// app/src/simple/java/io/nekohasekai/sagernet/simple/subs/NoticeViews.kt:246-252
val text = remember(notice.message, linkColor) { linkified(notice.message, linkColor) { openLink(context, it) } }
ModalBottomSheet(...) {
    Column(Modifier ... .verticalScroll(rememberScrollState())) {
```

Разметка ссылок (`linkified`, `NoticeViews.kt:332-350`) выполняется в композиции, на главном потоке; затем весь текст
раскладывается одним `Text` внутри прокрутки, без ленивой разбивки. Карточка на главном экране показывает 3–6 строк,
но получает ту же строку целиком.

Ссылки при этом безопасны: распознаются только `http(s)://`, `tg://`, `t.me/` и `www.` (`NoticeViews.kt:301`).

### Влияние
Обычные объявления — сотни символов, и с ними всё в порядке. Если панель провайдера по ошибке отдаёт в заголовке
HTML-страницу или журнал (десятки–сотни КБ), открытие листа «Объявление» раскладывает сотни тысяч символов на главном
потоке. Ожидаемые последствия — пропуск кадров и заметная задержка открытия, на слабых устройствах возможен ANR.
Масштаб не измерен: разметка ссылок линейна, основная цена — раскладка текста. Каждое обновление сообщений держит эту
строку в памяти и в метаданных группы в базе.

### Как воспроизвести
Шаги не прогонялись; они нужны, чтобы подтвердить или снять гипотезу.
1. Локальный сервер подписки (`adb reverse tcp:8099 tcp:8099`) отдаёт валидный список серверов по HTTP/1.1 и заголовок
   `Announce: base64:<base64 от 150 000 символов текста со ссылками через каждые ~100 символов>`.
2. Добавить подписку в simple и обновить. На главном экране появится карточка объявления → открыть её целиком.
3. Наблюдать `adb logcat -s Choreographer` («Skipped N frames») и время до появления листа; при подозрении на ANR —
   `adb shell dumpsys activity anr`. Для сравнения повторить с объявлением на 4 000 символов.
4. Гипотеза подтверждена, если открытие листа с длинным текстом занимает сотни миллисекунд и больше.

## What Changes
- Рекомендуется: ограничить длину объявления в коде Crown при построении состояния подписки
  (`SubscriptionState`, там, где уже делается `trim()`), например 4 000 символов с многоточием. Хеш для «Скрыть»/«Позже»
  считать от обрезанного текста, чтобы поведение кнопок не изменилось.
- По желанию: тот же предел в `SubscriptionMetadata.read`, чтобы длинная строка не попадала в базу. Это код upstream.
- Проверка: шаг 3 с длинным объявлением — лист открывается без пропуска кадров, текст обрезан.

## Impact
- **Код:** `app/src/simple/java/io/nekohasekai/sagernet/simple/subs/SubscriptionState.kt`; по желанию —
  `group/SubscriptionMetadata.kt`.
- **Upstream:** основная правка — код Crown. Предел в `SubscriptionMetadata.kt` — код upstream вне списков: новая точка
  правки или патч в upstream.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** слишком низкий предел обрежет законно длинную инструкцию провайдера; 4–8 тысяч символов — несколько экранов.
- **Проверка исправления:** шаги 1–3; юнит-тест обрезки и хеша.
- **Внешние источники:**
  - Jetpack Compose, производительность и работа в композиции: https://developer.android.com/develop/ui/compose/performance/bestpractices
  - ANR: https://developer.android.com/topic/performance/vitals/anr
