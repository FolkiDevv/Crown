# Proposal

> **Категория:** надёжность · **Приоритет:** высокий · **Проверка:** воспроизведено на эмуляторе (симптом); причина в ядре —
> гипотеза · **Код:** Crown (параметры управляемого «Авто») + ядро throne · **Объём:** S (параметры и замеры), M–L при доработке ядра

## Why

### Находка
Простой интерфейс создаёт управляемый автовыбор «Авто», задавая только группы, стратегию и ярус; остальное — значения по
умолчанию класса `AutoSelector`:

```kotlin
// app/src/simple/java/io/nekohasekai/sagernet/simple/modes/TrafficModes.kt:273-278
val selector = AutoSelector().apply {
    this.name = context.getString(name)
    gids = ArrayList(groups)
    strategy = AutoSelector.STRATEGY_PRIORITY
    tiers = arrayListOf(AutoSelector.Tier(-1, firstTier))
}
```

Значения по умолчанию (`outbound/types/AutoSelector.kt:45-79`): `intervalSec = 300`, `watchIntervalSec = 15`, `dialRetries = 2`,
`expected = 3`, `passive = false` — оценка по реальным соединениям приложений выключена. Они уходят в ядро как поля группы
`auto-selector` (`outbound/config/ConfigGenerator.kt:998-1034`; `passive` добавляется только при `true`). Для уже созданного
«Авто» `ensureSelector` обновляет лишь группы, ярусы и стратегию (`TrafficModes.kt:258-266`), то есть любые новые параметры
до существующих пользователей сами не дойдут.

Само решение о переключении принимает ядро (исходников в репозитории нет). По журналу ядра во время отказа текущего сервера
оно раз за разом проверяет только упавшего участника (`outbound/shadowsocks[pool-1-0]: outbound connection to
cp.cloudflare.com:80` каждые 5–15 с с 00:21:13 до 00:26:29), а запасной, давно не проверявшийся, впервые проверяется лишь в
00:26:31; переключение — около 00:27:00. Kotlin-сторона в это время ничего не ускоряет: принудительная перепроверка
(`AutoSelectorRuntime.recheck()`, `bg/autoselector/AutoSelectorRuntime.kt:269-281`) вызывается только кнопкой, а баннер
«Сервер не отвечает» simple UI (`simple/home/HomeStatus.kt:116`) лишь сообщает о проблеме.

### Влияние
Сервер падает или блокируется (частый случай: блокировка по IP молча отбрасывает пакеты), второй сервер в «Авто» исправен — а
пользователь 40–100 с не может открыть ни одного сайта; первые ≈40 с главная показывает «Защищено» без предупреждений.
Требование `auto-selector`, «Automatic node selection» («WHEN the active node fails its test while another candidate passes
THEN the app switches…»), формально выполняется, но полторы минуты без связи пользователь воспринимает как отказ VPN.

Замеры (эмулятор Android 17, debug-сборка коммита `0a0fcc4e`; подписка из двух рабочих тестовых shadowsocks-серверов и одного
«чёрной дыры»; «Авто»; запрос через туннель раз в секунду с таймаутом 3 с):

| Отказ текущего сервера | От первого неудачного запроса до первого удачного через другой сервер |
|---|---|
| Порт закрыт, соединение сбрасывается (`docker stop`) | 41 с |
| Соединение принимается, ответа нет (`docker pause`), сервер B; запасной A исправен 2,5 мин | 96 с |
| То же, сервер A; запасной B | 81 с |

Баннер «Сервер не отвечает» появился через ≈40 с. Возврат сервера (`docker start`) не вызвал «дребезга» — «Авто» осталось на
рабочем сервере 2 мин наблюдения.

### Как воспроизвести
1. Два тестовых сервера (sing-box в Docker), подписка с ними, simple UI, «Авто», подключиться.
2. На устройстве цикл запросов через туннель раз в секунду с таймаутом 3 с; по журналам серверов видно, через какой идёт трафик.
3. `docker pause <текущий сервер>`; засечь время до первого удачного запроса через второй.
4. Фактически: 80–100 с без трафика (с `docker stop` — ≈40 с); в `files/core.log` — проверки только упавшего участника.

## What Changes
1. **(Рекомендуется) Включить пассивную оценку в управляемом «Авто»** (`passive = true`): по описанию настройки
   (`autosel_passive_tip`) участник, у которого недавние реальные соединения неудачны не реже, чем удачны, три раза и больше,
   откладывается, даже если проверки проходят. Это изменение в коде Crown (`TrafficModes.ensureSelector`), upstream не трогается.
2. **Подобрать параметры проверок** управляемого селектора замером: меньше `watchIntervalSec` (например, 5 с) и `dialRetries`
   (1), чтобы упавший участник быстрее признавался негодным; `expected` не меньше 2, чтобы запасной оставался подтверждённым.
3. **Доставить параметры существующим пользователям**: ветка `kept` в `ensureSelector` выставляет и эти поля, если они
   совпадают со старыми значениями по умолчанию (не затирая ручную настройку из классического редактора).
4. **Ускорение со стороны приложения**: когда simple UI или `:bg` видит «Сервер не отвечает» при живой сети, один раз вызывать
   `AutoSelectorRuntime.recheck()` (с ограничением частоты), не дожидаясь расписания ядра.
5. Если п.1–4 не дадут < 15–20 с — доработка ядра: при отказе текущего участника сначала проверять запасных, а не повторять
   проверки упавшего. Это требует изменения throne (вне репозитория).

Как проверить: тот же стенд, по 10 отказов каждого вида (`stop` и `pause`) — цель < 15 с до первого удачного запроса через
запасной сервер; отдельно 30 мин на «плохой» сети без ложных переключений; фоновый трафик проверок до/после (байты и запросы за
час при выключенном экране).

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `auto-selector`: «Automatic node selection» — задать ожидаемое время переключения на исправного кандидата при отказе
  активного (например, «не дольше 20 с при наличии подтверждённого запасного»).
- `simple-ui-redesign/specs/simple-ui`: управляемое «Авто» использует параметры быстрого переключения; «Сервер не отвечает»
  запускает перепроверку.

## Impact
- **Код:** `simple/modes/TrafficModes.kt` (параметры, миграция существующего «Авто»), simple UI или `:bg` для вызова
  `recheck()`; `AutoSelector.kt` и `ConfigGenerator.kt` не меняются.
- **Upstream:** только код Crown; при п.5 — изменение ядра throne.
- **Ядро throne, сборка:** логика выбора — в ядре; что именно ускорит переключение, из Kotlin доказать нельзя, поэтому
  обязательна серия замеров. Сборка не затрагивается.
- **Риски:** пассивная оценка и частые проверки — больше фоновых запросов (батарея, трафик) и риск ложных переключений на
  нестабильной сотовой сети; `interruptOnSwitch = true` рвёт открытые соединения при каждом переключении — ложные
  переключения будут заметны.
- **Проверка исправления:** стенд выше; JVM-тест, что `ensureSelector` выставляет новые параметры и не трогает изменённые вручную.
- **Внешние источники:** не требуются (поведение определяется кодом приложения и ядра).
