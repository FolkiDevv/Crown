# Proposal

> **Категория:** надёжность · **Приоритет:** низкий · **Проверка:** воспроизведено на эмуляторе ·
> **Код:** upstream · **Объём:** S

## Why

### Находка
В классическом интерфейсе нажатие на нижнюю панель при подключённом VPN запускает проверку текущего соединения
(`ui/MainActivity.kt:147` → `StatsBar.testConnection`). На время проверки панель показывает «Тестирование…». При
успехе её сменяет задержка, а при ошибке ставится **тот же** текст:

```kotlin
// app/src/main/java/io/nekohasekai/sagernet/widget/StatsBar.kt:435-446
} catch (e: Exception) {
    Logs.w(e.toString())
    onMainDispatcher {
        isEnabled = true
        setStatus(app.getText(R.string.connection_test_testing))   // «Тестирование…»
        activity.snackbar(app.getString(R.string.connection_test_error, e.readableMessage)).show()
    }
}
```

Ошибка — частый исход: `urlTest` бросает исключение при недоступном тестовом адресе, таймауте или неработающем
сервере (`bg/BaseService.kt:231-243`). Снекбар с ошибкой исчезает через ~3 с, а панель и её подсказка показывают
«Тестирование…», пока не сменится состояние сервиса.

### Влияние
Соединение проверяют, когда что-то не работает. Пользователь видит бесконечное «Тестирование…» и решает, что
проверка зависла, хотя она закончилась ошибкой. Нарушается `openspec/specs/connectivity-testing` «Single profile URL
test»: приложение ДОЛЖНО сообщить задержку или состояние «таймаут / ошибка». Касается только классического
интерфейса: новый показывает результат проверки на своей главной.

### Как воспроизвести
Debug-сборка `dev.folki.crown.debug`, эмулятор Android 17 (API 37), классический интерфейс (Настройки →
«Classic interface»).

1. Подключить VPN к локальному socks-серверу, затем остановить сервер (сервер «умер»).
2. Нажать на нижнюю панель «… Connected, tap to check connection».
3. Наблюдать:
   ```
   +1 с:  «▲ 0 B/s, ▼ 0 B/s, Latvia, Testing…»
   +13 с: «▲ 0 B/s, ▼ 0 B/s, Testing…»
   +23 с: «▲ 0 B/s, ▼ 0 B/s, Testing…»
   ```
   По журналу ядра проверка уже завершилась: следом за ней запустилось обновление внешнего IP (`ExitIp.refresh()`
   вызывается после проверки — строки `[ExitIp] exit IP lookup: … Connection reset`). Панель так и осталась
   «Testing…».

## What Changes
1. В ветке ошибки показывать в панели итог, а не «Тестирование…»: короткий текст вроде «Нет соединения — нажмите,
   чтобы проверить снова» (новая строка во всех переводах) или вернуть обычный текст подключённого состояния.
   Рекомендуется итог: он остаётся виден после того, как снекбар исчезнет.
2. Подсказку (tooltip) обновлять тем же текстом — это делает `setStatus`.
3. Проверка «до/после»: шаги 1–3 — после ошибки панель показывает итог, повторное нажатие запускает новую проверку.

### Modified Capabilities

  панель показывает состояние ошибки, а не «Тестирование…».

## Impact
- **Код:** `app/src/main/java/io/nekohasekai/sagernet/widget/StatsBar.kt`, строки (`res/values*/strings.xml`).
- **Upstream:** файл upstream, точки правки форка нет (`tools/diagnostics/upstream_touch_points.py`) — патч в upstream
  или новая точка правки.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** нет.
- **Проверка исправления:** сценарий выше; проверка при успешном тесте не меняется.
