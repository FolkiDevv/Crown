# Proposal

> **Категория:** надёжность, стабильность · **Приоритет:** низкий · **Проверка:** подтверждено по коду (потеря
> правок); падение по размеру — гипотеза · **Код:** upstream · **Объём:** S

## Why

### Находка
Редактор JSON (`JsonEditorActivity`) открывается для «Изменить как JSON» любого профиля, для конфига
custom-профиля и для JSON-настроек (`custom_inbound`, `dns_object`). Текст правки живёт только в редакторе. При
каждой остановке activity он кладётся в saved state, но лишь до порога:

```kotlin
// app/src/main/java/io/nekohasekai/sagernet/ui/json/JsonEditorActivity.kt:79, 543-549
private const val MAX_SAVED_CHARS = 256 * 1024
override fun onSaveInstanceState(outState: Bundle) {
    super.onSaveInstanceState(outState)
    val text = editor.text.toString()
    if (text.length + baseline.length <= MAX_SAVED_CHARS) {
        outState.putString(STATE_TEXT, text)
        outState.putString(STATE_BASELINE, baseline)
    }
}
```

Поворот и изменение размера окна activity обрабатывает сама (`AndroidManifest.xml:213-215`, `configChanges`),
поэтому saved state нужен в основном при смерти процесса. Отсюда две проблемы.

1. **Выше порога правки теряются молча.** Если текст и исходное значение вместе длиннее 256 К символов (каждый —
   от ~128 К), ничего не сохраняется. После смерти процесса `onCreate` берёт `load()` (`JsonEditorActivity.kt:157-164,
   186-192`) из хранилища. Для профиля это `profileCacheStore` — база в памяти (`database/DataStore.kt:29`,
   `moe/matsuri/nb4a/TempDatabase.kt:17`, `Room.inMemoryDatabaseBuilder`), после смерти процесса она пуста.
   Редактор показывает старое значение или пустоту, а `close()` (`:424-435`) не спрашивает о несохранённых
   правках: текст равен исходному.
2. **Ниже порога saved state большой.** До 256 К символов — это около 512 КБ в Parcel (2 байта на символ) при каждом
   уходе в фон. Буфер binder-транзакций процесса — около 1 МБ на все одновременные вызовы. На targetSdk 24+
   переполнение при сохранении состояния роняет процесс. На эмуляторе отказ доставки начинался с ~955 КБ (замер для
   соседней находки про Intent в редакторах маршрутов), так что 512 КБ в одиночку ниже порога. Падение возможно
   только вместе с другими транзакциями или состоянием View и не воспроизводилось.

### Влияние
- Пользователь правит большой полный конфиг (Xray или sing-box со встроенными списками), уходит в другое
  приложение, система убивает процесс в фоне — при возврате правки пропали без предупреждения. Сценарий редкий:
  нужен конфиг больше ~128 К символов и смерть процесса во время правки.
- Возможное падение интерфейса при сворачивании редактора с конфигом на 100–128 К символов под нагрузкой на binder.
  Не измерено.
- `openspec/specs/outbound-protocols` «Custom and raw configs» обещает редактирование сырого конфига в
  JSON-редакторе; потеря правок этому противоречит.

### Как воспроизвести
По коду. Шаги для проверки на устройстве:
1. Custom-профиль с конфигом около 140 К символов. Открыть редактор, изменить строку, нажать Home.
2. `adb shell am kill dev.folki.crown.debug` (процесс в фоне), вернуться из «Недавних».
3. Ожидаемый неверный результат: редактор открывается без правки (или пустым), «Назад» закрывает его без вопроса.
4. Для размера: конфиг около 120 К символов, правка, Home; в `adb logcat` искать `TransactionTooLargeException` /
   `data parcel size`, повторить во время обновления подписки или теста скорости.

## What Changes
1. **(Рекомендуется.)** Хранить черновик не в Bundle, а во временном файле во внутреннем `cacheDir`: имя — по ключу
   редактируемого значения, запись в `onStop` в фоновом потоке. В Bundle — только признак «черновик есть». При
   восстановлении читать файл, при закрытии редактора (сохранить или отказаться) удалять. Это убирает риск по
   размеру и переживает смерть процесса для любых объёмов.
2. Минимальная мера: снизить порог до ~50 К символов (десятки КБ — рекомендуемый размер saved state), а выше
   порога честно предупреждать: «Большой текст не переживёт закрытие приложения системой — сохраните изменения».
3. Проверка «до/после»: шаги 1–3 восстанавливают правку; в шаге 4 размер Bundle — десятки байт.

## Impact
- **Код:** `app/src/main/java/io/nekohasekai/sagernet/ui/json/JsonEditorActivity.kt`.
- **Upstream:** файл upstream, точки правки форка нет (`tools/diagnostics/upstream_touch_points.py`) — патч в upstream
  или новая точка правки.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** черновик содержит конфиг с ключами — только внутренний `cacheDir`, удаление при выходе из редактора и
  по возрасту для черновиков, оставшихся от убитого процесса. Потеря самого кэша профиля после смерти процесса — это
  отдельная проблема экрана профиля, этим изменением она не закрывается.
- **Проверка исправления:** сценарий выше; инструментальный тест «сохранить состояние → пересоздать activity» с
  текстом 300 К символов.
- **Внешние источники:** «Saved state» и «TransactionTooLargeException»
  (https://developer.android.com/topic/libraries/architecture/saving-states,
  https://developer.android.com/reference/android/os/TransactionTooLargeException).
