# Proposal

> **Категория:** надёжность · **Приоритет:** низкий · **Проверка:** подтверждено по коду · **Код:** upstream · **Объём:** S

## Why

### Находка
`TrafficLooper` копит трафик профилей за сеанс только в памяти процесса `:bg`
(`app/src/main/java/io/nekohasekai/sagernet/bg/proto/TrafficLooper.kt:39`, `profiles`). Раз в секунду цикл `loop()`
(`:195-270`) читает дельты из ядра и рассылает их видимому UI, но в БД ничего не пишет. Запись — `persist()` (`:102-110`,
`proxyDao.addTraffic` приращением) — вызывается только из `stop()`:
```kotlin
// TrafficLooper.kt:72-84 (сокращено)
stateMutex.withLock {
    // Polling pauses with the screen off; the core's counters outlive the box, so collect the rest now.
    try { collect() } catch (e: Throwable) { Logs.w(e) }
    SagerDatabase.instance.runInTransaction {
        for (item in profiles.values) { if (item.id <= 0L) continue; persist(item) ... }
```
`stop()` вызывает только `ProxyInstance.close()` (`bg/proto/ProxyInstance.kt:86-90`) — штатная остановка или перезапуск.
При выключенном экране цикл вообще не опрашивает ядро (`TrafficLooper.kt:205-209`): накопленное за ночь живёт только в
счётчиках ядра. Обработчик выключения устройства — заглушка: `bg/BaseService.kt:83`
`Intent.ACTION_SHUTDOWN -> service.persistStats()` и `:551-553` `fun persistStats() { // TODO NEW save app stats? }`.

Если `:bg` завершается без `stop()`, весь трафик сеанса пропадает: обновление приложения при включённом VPN, выключение
или перезагрузка телефона, падение ядра, убийство системой при нехватке памяти или фоновыми ограничениями прошивки,
«Остановить принудительно», перезапуск процесса через `Runtime.getRuntime().exit(0)` (`BaseService.kt:189-191`).

### Влияние
Счётчики трафика профиля (`traffic_dl`/`traffic_up`) показывает классический интерфейс, по ним работает сортировка «по
трафику». После нештатного завершения `:bg` трафик профиля откатывается к значению на момент прошлой штатной остановки —
теряются часы и дни учёта (VPN часто держат включённым неделями). Это расходится с `profile-management`, требование
«Profile persistence»: «… traffic statistics … SHALL keep statistics across app restarts». Simple трафик профилей не
показывает (`app/src/simple/.../simple/servers/ServersViewModel.kt:502`: `onUpdated(...) = Unit`), поэтому приоритет низкий:
теряется статистика, а не профили или настройки.

### Как воспроизвести
Шаги выведены из кода и не прогонялись.
1. Классический интерфейс, подключить VPN, скачать 50–100 МБ; в списке серверов растёт трафик профиля.
2. Убить процесс `:bg`: `adb shell pidof dev.folki.crown.debug:bg`, затем `adb shell kill -9 <pid>` (эмулятор с root) или
   установить ту же сборку поверх (`adb install -r`).
3. Открыть приложение, открыть список серверов.
4. Ожидаемый неверный результат: трафик профиля равен значению до шага 1. Для сравнения — при остановке кнопкой трафик
   сохраняется. Проверка в БД: `select id, traffic_dl, traffic_up from proxy_entities` до и после.

## What Changes
- Рекомендуется: периодически сбрасывать накопленное тем же `persist()` — раз в 1–5 минут при работающем опросе, одной
  транзакцией только для изменившихся профилей. Запись инкрементальная, поэтому сброс в `stop()` остаётся корректным и не
  задваивает.
- Перед паузой опроса при выключении экрана (`TrafficLooper.kt:205-209`) выполнять `collect()` и запись — закрывает долгие
  сеансы с погашенным экраном.
- Реализовать `persistStats()` для `ACTION_SHUTDOWN`: `collect()` и запись с коротким сроком.
- Проверка: сценарий выше теряет не больше одного интервала сброса.

## Impact
- **Код:** `bg/proto/TrafficLooper.kt`, `bg/BaseService.kt` (`persistStats`).
- **Upstream:** `BaseService.kt` — существующая точка правки 6 (описание расширить); `TrafficLooper.kt` — новая точка правки
  или патч в upstream, там та же заглушка.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** каждая запись в таблицу профилей вызывает инвалидацию Room между процессами и перечитывание списков в UI —
  поэтому интервал в минуты, а не секунды, и только изменившиеся профили. Альтернатива дешевле — писать только при
  выключении экрана и при `ACTION_SHUTDOWN`: закрывает перезагрузку и ночные сеансы, но не обновление приложения при
  включённом экране.
- **Проверка исправления:** шаги «Как воспроизвести»; проверка, что список серверов не мигает при периодической записи.
- **Внешние источники:**
  - `Intent.ACTION_SHUTDOWN`: https://developer.android.com/reference/android/content/Intent#ACTION_SHUTDOWN
