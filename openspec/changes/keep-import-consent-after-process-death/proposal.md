# Proposal

> **Категория:** надёжность · **Приоритет:** низкий ·
> **Проверка:** подтверждено по коду ·
> **Код:** Crown · **Объём:** S

## Why

### Находка

Ссылку из браузера или другого приложения `SimpleActivity` передаёт в поток добавления один раз — при первом создании:

```kotlin
// app/src/simple/java/io/nekohasekai/sagernet/simple/SimpleActivity.kt:298-305
if (savedInstanceState == null) {
    ...
    handleImportIntent(intent)            // → add.importText(it, external = true)
} else {
    batteryPrompt.value = savedInstanceState.getBoolean(STATE_BATTERY_PROMPT)
    leftApp = savedInstanceState.getBoolean(STATE_LEFT_APP)
}
```

Вопрос «Добавить подписку?/Добавить серверы?» живёт только в полях `AddViewModel`: план `confirming` и `AddUiState.confirm`
(`simple/add/AddViewModel.kt:68, 108, 319-327`). У этой ViewModel нет `SavedStateHandle` (`AddViewModel.kt:88`,
`class AddViewModel(application: Application)`), а `onSaveInstanceState` activity сохраняет только признаки батарейного
диалога и ухода из приложения (`SimpleActivity.kt:308-313`). Диалог рисуется по `addState.confirm` (`SimpleActivity.kt:987-990`).

Поворот ViewModel переживает — там всё в порядке. Но если процесс UI выгружен, пока диалог открыт, при возврате activity
восстанавливается с `savedInstanceState != null`: `handleImportIntent` не вызывается, новая `AddViewModel` пуста — диалога
нет, ссылка не добавлена, и пользователю об этом ничего не сказано.

Это обратный случай к повтору при входе из «Недавних» без сохранённого состояния (изменение
`dont-repeat-one-shot-intents-from-recents`): там вопрос повторяется лишний раз, здесь — теряется.

### Влияние

Пользователь нажал «Подключить в Crown» на странице провайдера, увидел «Добавить подписку?», ушёл сверить адрес в браузер или
менеджер паролей; система выгрузила процесс. По возвращении — главная без диалога, подписки нет; пользователь решает, что
ссылка не сработала. Спецификация simple-ui («Подтверждение ссылки из другого приложения») требует добавления после
подтверждения; вопрос не должен исчезать без ответа. Происходит только при смерти процесса в фоне (чаще на слабых
устройствах), поэтому приоритет низкий; данные не теряются — ссылку можно открыть снова.

Однотипные, но безвредные потери того же рода: итог импорта («Подписка добавлена — Подключиться») и предложение из буфера
обмена — пользователь может повторить действие сам.

### Как воспроизвести

На эмуляторе не проверялось (проверено по коду). Шаги для проверки:

1. `adb shell am start -a android.intent.action.VIEW -d 'crown://addsub?url=https%3A%2F%2Fsub.example.com%2Fabc&name=Test' <пакет>` —
   показан «Добавить подписку?».
2. Нажать Home, затем `adb shell am kill <пакет>` (убивает фоновый процесс, сохраняя задачу и состояние activity).
3. Открыть Crown из «Недавних».
4. Ожидаемый неверный результат: главная без диалога, подписка не добавлена.
Вариант без `am kill`: «Для разработчиков → Не сохранять действия» (тот же путь `savedInstanceState != null` с новой ViewModel).

## What Changes

1. (Рекомендуется.) Хранить ожидающий вопрос в `SavedStateHandle` `AddViewModel`: исходный текст ссылки (он уже прошёл
   проверку и мал) и признак `external`. При создании ViewModel с непустым значением заново построить план
   (`SimpleImport.plan`) и показать `confirm`; очищать по «Добавить»/«Отмена».
2. Альтернатива без изменения ViewModel — в `SimpleActivity` при `savedInstanceState != null` перечитывать ещё не отвеченный
   intent (флаг «ответ дан» в `onSaveInstanceState`). Сложнее согласовать с повтором из «Недавних».
3. Ограничить длину сохраняемого текста (ссылки, а не документы на мегабайты); длинный текст не сохранять.

Как проверить: шаги 1–3 показывают диалог снова; после «Отмена» и смерти процесса диалог не возвращается.

## Impact

- **Код:** `simple/add/AddViewModel.kt` (конструктор с `SavedStateHandle`, `ask`, `confirmLink`, `cancelLink`).
- **Upstream:** код Crown, точки правки не нужны.
- **Ядро throne, сборка, инструменты:** не затрагиваются.
- **Риски:** в состоянии задачи окажется ссылка подписки (персональная, с токеном); она уже лежит в intent'е той же задачи,
  поэтому новой утечки нет. Не показать вопрос дважды (после ответа очищать до выполнения).
- **Проверка исправления:** сценарий эмулятора «до/после»; unit-тест ViewModel с `SavedStateHandle`, содержащим ожидающую
  ссылку, — `state.confirm` не пуст.
