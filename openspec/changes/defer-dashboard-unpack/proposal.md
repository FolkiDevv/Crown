# Proposal

> **Категория:** скорость · **Приоритет:** низкий · **Проверка:** воспроизведено на эмуляторе · **Код:** upstream ·
> **Объём:** S

## Why

### Находка
Веб-дашборд sing-box включён по умолчанию (`database/SettingsRegistry.kt:359`, `core_box_api_port = 9091`;
`DataStore.apiDashboardEnabled = coreBoxApiPort > 0`). На каждом старте VPN, до запуска ядра, его распаковка проверяется и
при необходимости выполняется прямо в пути подключения:

```kotlin
// app/src/main/java/io/nekohasekai/sagernet/bg/proto/BoxInstance.kt:75-76
// Before the start: the core downloads the dashboard itself when it finds the dir empty.
if (DataStore.apiDashboardEnabled) withContext(Dispatchers.IO) { SingBoxDashboard.install() }
```

`SingBoxDashboard.install()` (`bg/SingBoxDashboard.kt:44-69`) сравнивает штамп с `lastUpdateTime` пакета (`:30-38`) и после
каждой установки или обновления приложения рекурсивно обходит `assets/sb-dashboard` (`assetFiles`, `:72-79`: `assets.list`
на каждый файл и каталог), копирует каждый файл во временный каталог, удаляет старый и переименовывает. Старт ядра ждёт
окончания. Сам дашборд нужен только тому, кто откроет его экран.

В текущей сборке дашборд — 46 файлов, 8,2 МБ.

### Влияние
Первое «Подключить» после каждой установки и каждого обновления Crown (обновления частые) задерживается на время копирования
8 МБ — как раз когда пользователь проверяет, работает ли новая версия; то же для автозапуска после обновления. Ошибка
распаковки старт не валит, поэтому это только скорость.

Замер на эмуляторе Android 17 (x86_64 на настольном ПК, быстрый диск) — время от первого записанного файла до штампа, то
есть **только копирование**, без обхода `assets.list`:

| Случай | Копирование |
|---|---|
| Первая установка, первое подключение | 400 мс |
| После `adb install -r` той же сборки, 3 повтора | 116, 116, 152 мс |
| Последующие подключения | распаковки нет |

На телефоне с медленной eMMC и холодным кэшем время будет больше (оценка — сотни миллисекунд); точное число на устройстве не
измерено.

### Как воспроизвести
1. Debug-сборка с дашбордом, журнал уровня info, VPN выключен.
2. `adb install -r <тот же APK>` (меняется `lastUpdateTime`), открыть приложение, «Подключить».
3. В `files/core.log`: `[SingBoxDashboard] dashboard: unpacked 46 files` непосредственно перед `Start: {…}`
   (например, `05:11:43 … unpacked 46 files` → `05:11:44 Start:`).
4. Длительность копирования: `run-as <пакет>` и `stat -c %y` по файлам `files/core/sb-dashboard/**` и
   `files/core/sb-dashboard.stamp` — разница между самым ранним файлом и штампом.
5. Повторное подключение — строки `unpacked` нет.

## What Changes
1. (рекомендуется) Вынести распаковку из пути старта: запускать её в фоне при создании процесса `:bg` после обновления
   (`SagerNet.onCreate` в `:bg` → фоновая корутина) и/или лениво при открытии экрана дашборда. Перед стартом ядра оставить
   только быструю проверку: если распаковка не закончена, ядру всё равно нужен непустой каталог или признак «не скачивать»,
   иначе ядро, по комментарию в `BoxInstance.kt:75`, само пойдёт в сеть за дашбордом — это надо проверить на ядре и при
   необходимости передавать ему пустой `external_ui_download_url`/отключать автообновление дашборда.
2. Хранить дашборд в assets одним архивом и распаковывать потоково — меньше вызовов `assets.list`/`open`.

Проверка: время от «Подключить» до `Connected` при первом старте после `adb install -r` сравнивается со вторым стартом —
разница должна исчезнуть; дашборд открывается и после фоновой распаковки.

## Impact
- **Код:** `bg/proto/BoxInstance.kt` (`init`), `bg/SingBoxDashboard.kt`, `SagerNet.kt` (фоновый запуск в `:bg`).
- **Upstream:** **патч в upstream** — `BoxInstance.kt` и `SingBoxDashboard.kt` не входят в `TOUCH_POINTS`; `SagerNet.kt` —
  точка идентичности форка только для отображаемой версии, фоновая распаковка туда не относится.
- **Ядро throne, сборка, инструменты:** поведение ядра при пустом каталоге дашборда (загрузка из сети) — предположение из
  комментария, проверить на ядре. При варианте 2 меняется упаковка ассетов в CI
  (`.github/actions/sing-box-dashboard/action.yml`).
- **Риски:** гонка фоновой распаковки с загрузкой, которую ядро может начать само (`SingBoxDashboard.kt:60-61` уже заменяет
  скачанную ядром копию); экран дашборда, открытый до окончания распаковки, должен её дождаться.
- **Проверка исправления:** замер «до/после» по шагам выше на эмуляторе и одном реальном устройстве.
